# 松鼠投放 · 设计系统 Design System

> B 端短剧投放 AI 助手的统一设计规范。单一真相来源（SSOT）= `frontend/src/style.css` 的 `:root` tokens + 全局组件类。本文档梳理其规范与设计决策，供团队查阅、面试讲解共用。
>
> **设计锚点**：主色品牌蓝 `#2563EB`，严格不用靛蓝 / 紫。

---

## 0. 设计原则（总纲）

| 原则 | 含义 | 为什么 |
|---|---|---|
| **B 端系统规范优先** | 用系统化、克制的表达，避免营销展示感（大色块、夸张渐变、煽动文案） | 用户是专业投手 / 主管，每天高频使用，要的是效率与信息密度，不是被「种草」 |
| **品牌蓝锚定** | 主操作 / 高亮统一用品牌蓝 `#2563EB` 系，不用靛蓝 / 紫 | 保持品牌一致性，避免色彩漂移 |
| **少而真 > 多而假** | 宁可功能少但每个都真实可用，不堆砌点不动的占位 | 占位越多，可被戳穿的「假功能」越多；克制反而显专业 |
| **数据单一真相（SSOT）** | 同一实体（账户 / 知识）全站一处定义、多处派生 | 避免同一账户在不同页对不上号（负责人 / 消耗 / 名称漂移） |
| **判断与事实分层** | 监控 = 纯事实数据，不做任何判断；判断（归因 / 建议）收口到复盘 | 职责清晰：看数去监控，要结论去复盘，不在监控里塞「异常」红字误导 |

## 1. 色彩 Color

### 1.1 品牌色阶

| Token | 值 | 用途 |
|---|---|---|
| `--brand-50` | `#EEF4FF` | 主操作 hover 底、选中态浅底、tag-brand 底 |
| `--brand-300` | `#8EAEFB` | 输入聚焦边框 |
| `--brand-400` | `#5E89F6` | outline 按钮 hover 边 |
| `--brand-600` | `#2554DC` | **主按钮 / 主操作底色** |
| `--brand-700` | `#1E44BC` | 主按钮 hover、强调文字 |
| `--brand-pri` | `#2563EB` | **品牌锚点**，关键强调处确保此值出现 |

> 完整色阶 `--brand-50 ~ --brand-900` 共 10 档，按需取深浅。

### 1.2 语义色

| 语义 | 前景 | 背景 | 用途 |
|---|---|---|---|
| 成功 success | `#16A34A` | `#ECFDF5` | 授权正常、可投、过审 |
| 警告 warning | `#F59E0B` | `#FFFBEB` | 即将过期、建议优化、需关注 |
| 危险 danger | `#DC2626` | `#FEF2F2` | 拒审、高风险、解除授权、退出 |
| 信息 info | `#2563EB` | `#EFF6FF` | 同步中、提示（= 品牌蓝） |

辅助色（点缀，慎用）：`--accent-orange #FF7A2F`（私域 / 平台徽章）、`--accent-amber #F5A524`。

### 1.3 中性灰阶

`--gray-50 #F8FAFC` → `--gray-900 #0F172A` 共 10 档。常用：正文 `--gray-800`、次要文字 `--gray-500`、占位 / 禁用 `--gray-400`、分隔线 `--gray-200`。

### 1.4 背景与描边

| Token | 值 | 用途 |
|---|---|---|
| `--bg-page` | `#F5F7FB` | 页面底 |
| `--bg-card` | `#FFFFFF` | 卡片 / 侧栏 / 顶栏 |
| `--border-base` | `#E5E9F2` | 默认描边 |
| `--border-light` | `#F0F2F8` | 表格行 / 弱分隔 |

**✅ Do**：主操作用 `--brand-600`；状态语义化（成功绿 / 危险红）。
**🚫 Don't**：不用紫 / 靛蓝；不用大面积高饱和色块；危险色只给真·破坏性操作。

## 2. 字体排版 Typography

| Token | 值 | 用途 |
|---|---|---|
| `--font-xs` | 12px | 徽章、元信息、表格次要列 |
| `--font-sm` | 13px | 正文默认、按钮、表单 |
| `--font-base` | 14px | 全局基准 |
| `--font-2xl` | 20px | 页面主标题 `.page-title` |
| `--font-4xl` | 30px | KPI 大数字 |

字重：常规 `400`，强调 / 标题 `500~600`，**不超过 700**（B 端克制）。

**页面标题体系**：`.page-title`（20px / 600 / gray-900）+ `.page-subtitle`（13px / gray-500）。问答 / 诊断 / 复盘用对话式页头，其余用标准 page-header。

## 3. 间距 Spacing

8px 基准栅格，token：`--space-1 4px` / `2 8px` / `3 12px` / `4 16px` / `5 20px` / `6 24px` / `8 32px` / `10 40px` / `12 48px`。

常用：卡片内边距 `20-24px`、字段行 `12px`、组件间距 `8-16px`、区块间距 `20-24px`。

## 6. 组件库 Components

### 6.1 按钮 Button（`.btn`）

| 变体 | 类 | 用途 |
|---|---|---|
| 主操作 | `.btn-primary` | 品牌蓝底，每屏 ≤1 个主操作 |
| 次操作 | `.btn-secondary` | 灰底 |
| 描边 | `.btn-outline` | 白底蓝边 hover |
| 文字 | `.btn-ghost` | 无底，低优先级 |
| 危险 | `.btn-danger` | 红底，仅破坏性操作 |

尺寸 `.btn-sm`（4×10）/ 默认（6×14）/ `.btn-lg`（9×18）。禁用 `[disabled]` → opacity .6 + not-allowed。

### 6.2 标签 / 徽章 Tag（`.tag`，胶囊 `radius-full`）

`tag-brand` / `tag-success` / `tag-warn` / `tag-danger` / `tag-info` / `tag-gray` / `tag-orange`。用于状态、层级、平台标识。

### 6.3 卡片 Card

白底 + `--border-base` + `--radius-lg` + `--shadow-sm`，内边距 `20-24px`。KPI 卡 / 列表卡 / 报告卡同构。

### 6.4 表格 Table

表头 `gray-50` 底 + `gray-500` 文字；行分隔 `--border-light`；可点击行 hover 高亮。**监控表：纯数值列，无状态 / 涨跌 / 标红判断列。**

### 6.5 开关 Toggle / 6.6 下拉 Dropdown / 6.7 轻提示 Toast

- **Toggle**：36×20 胶囊，选中 `--brand-600`。
- **下拉**：`fixed` 定位 + `--shadow-lg`；**互斥（开一个关其余）+ 点击外部关闭 + 卸载移除监听**。
- **Toast**：底部居中胶囊（深色 `#0F172A`），`2.2s` 自动消失，用于轻反馈（已保存 / 已切换）。

### 6.8 抽屉 Drawer / 6.9 Tab / Chip / 6.10 输入

- **抽屉**：右侧滑入 + 遮罩，点遮罩关闭（来源详情 / 知识详情）。
- **筛选 Chip**：真下拉、互斥、已选高亮；无数据的 chip 自动隐藏（如空「待接受」）。
- **输入 Input/Select**：32px 高 + `radius-sm` + 聚焦 `--brand-300` 边。

## 7. 交互规范 Interaction

| 场景 | 规范 |
|---|---|
| **下拉浮层** | 互斥展开 + 点击外部关闭 + `onBeforeUnmount` 移除监听（防泄漏） |
| **破坏性操作** | 就地二次确认（「解除」→「确认解除？」，3s 复位），不直接执行 |
| **操作反馈** | Toast 轻提示，2.2s；真承接的操作给状态条（如复盘一键执行「✓ 已下发」） |
| **三态** | 列表必须有 加载（检索中…）/ 空（引导文案）/ 错误（可重试）三态 |
| **权限三层** | ①导航按角色过滤 ②路由守卫拦 URL 越权 ③切角色后越权页踢回 /qa |

## 8. B 端设计原则 B-side Principles

1. **系统规范，避免营销感** — 后台 / 投放工具按系统约定表达，不做 C 端种草式视觉。
2. **监控 = 事实层** — 纯数值，不做判断（无 status / severity / 标红 / 异常标记）；判断收口到复盘。
3. **权限按角色** — admin / 投手 / 审核 / 运营 四角色，导航 + 路由 + 切角色三层闭环。
4. **关键操作不放右上角** — 用户（尤其微信生态心智）会把右上角理解为关闭 / 退出区。
5. **退出登录只在「设置 · 安全中心」** — header / 顶栏不重复放退出。
6. **视频不支持、图片是能力** — 视频转文字 / 人工；图片诊断引导去「素材诊断」（并列正常入口，非降级兜底）。

## 9. 数据与文案规范 Data & Copy

### 9.1 账户主数据 SSOT
8 账户（巨量 5 / 磁力 2 / 腾讯 1）在 `mocks/accountsMaster.ts` 唯一定义，账户号 / 名 / 负责人 / 今日消耗 / 平台单一真相；监控 / 账户中心 / 团队 / 问答 / 复盘**全部派生或对齐**，不各写各的。

### 9.2 知识库三级
| 层 | 徽章 | 内容 |
|---|---|---|
| L1 平台规则库 | 🛡️ 平台 · 官方规则 | 巨量 / 磁力 / 腾讯官方规则（API 同步） |
| L2 公域经验库 | 🌐 公域 | 行业 benchmark、拒审案例（运营维护） |
| L3 私域经验库 | 🔒 私域 / 🤖 AI 沉淀 | 客户题材 / 出价 / 素材 / 复盘 / 个人偏好 |

**知识库 ↔ 问答打通**：问答引用的「来源」必须是知识库里真实存在的条目（标题 / 原文一致），支撑「私域知识库 → AI 召回 → 问答有据可查」的核心叙事。

### 9.3 术语与文案
- **命中率**（统一术语，不用「命中度」）。
- 文案**翻译用户意图**，不照搬产品解释、不解释界面结构（如不写「按最新顺序排列」）。
- 品牌展示地区用**城市级**（杭州 / 武汉），不用商圈 / 区级。
- `[Mock]` 仅开发期标识，**UI 不可见**，接真实接口后移除。

## 附录：可作为面试讲点的设计决策

- **为什么监控不做判断**：职责分层（事实 vs 判断），避免监控页变成「到处标红的焦虑墙」。
- **为什么账户要 SSOT**：演示中面试官交叉点两个页面对比数字，不一致即穿帮；一处定义多处派生根治。
- **为什么权限要三层**：导航藏入口 ≠ 真权限；URL 直达、切角色都得拦，才是完整闭环。
- **为什么设置页要克制**：堆点不动的 mock 开关，反而扩大「假功能」暴露面，少而真更经得起追问。
