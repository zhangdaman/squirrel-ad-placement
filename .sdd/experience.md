# 松鼠投放 · 项目经验

## 产品口径（改动必读）

- **监控 = 事实层**（是什么），**复盘 = 判断层**（为什么 / 好不好 / 怎么办），互不越界
- 监控页**纯数据、不做任何判断**（无 AI 解读 / 状态标签 / ROI 异常标记）——判断易失误，收口到复盘 Agent
- **平台全局化**：投手锁定单平台，管理者可切「全平台汇总」，状态存 localStorage
- **系统能自动判断的别让用户配**：平台自动 scope、角色驱动导航过滤、知识自动路由
- **不支持视频上传**：转文字描述 + 人工接入；英文/中文文案都不夸大预期（不暗示已上线/可直接下单）
- 默认首页 = 智能问答；工作台、智能预警暂隐藏（V2，预警已并入监控异常焦点条）
- 高风险/不可逆操作给二次确认；可逆操作（置顶）给即时反馈

## 视觉规范

- B 端 SaaS 严格按系统规范表达，避免营销展示感
- 主色锚定品牌蓝 `#2563EB`，**不用靛蓝 / 紫**
- 「一个数据，认准一个家」——同一数据不在 tab / 汇总条 / 表格里重复展示
- 列表精简（发现）↔ 详情丰富（下钻）分层

## 数据一致性（golden-data 账本）

- A001 现言旗舰户（今日）：消耗 ¥86,200 / ROI 0.84 / 转化目标量 36 / 支付粉价 91.77 / 点击率 3.10%
- 漏斗：曝光 446,600 → 点击 13,846(3.10%) → 加粉 939(¥91.77) → 付费 36(¥2,394)
- 平台分布：巨量 5 户 ¥373,400 + 磁力 2 户 ¥74,200 + 腾讯 1 户 ¥32,400 = ¥480,000
- 复盘叙事：5 天前 ROI 1.5 阶梯跌至 0.84；止损区间 ¥12–18 万 / 周

## 文案

- 前端文案翻译用户意图，不照搬原话；不解释界面结构（如「按最新顺序排列」这类系统说明）
- 品牌展示地区用城市级（杭州 / 武汉），不用商圈 / 区级

## 工程 / 前端协作（踩坑沉淀）

- **agent 组件化后必须扫 class↔style 覆盖**：把 prototype HTML 拆成 Vue 组件时，agent 常只搬 `<template>` 结构、漏搬 `<style>`，导致大量 class「裸奔」——如 KnowledgeCard 的 `kbc-*`、监控 `mon-view-detail`、复盘 `rv-report`、`thinking-bar` 在 build 产物里完全无样式，页面塌成无排版的 div 流。**每次 agent 产出页面 / 组件后跑脚本**：对每个 .vue 提取 `<template>` 用到的 class，与全局 `style.css` + 各 scoped `<style>` 已定义的 class 求差集；差集非空即缺样式，从对应 `docs/prototypes/*.html` 补回。只看 kebab-case 静态类可滤掉 `:class` 动态表达式噪音。
- 子组件样式别写进父页面的 `<style scoped>`：scoped 不穿透子组件内部元素，写了也不生效（除非 `:deep()`）。卡片类样式就近放进卡片组件自己的 scoped。
- mock 数据按 dev-standards 带 `[Mock]` 前缀，但**渲染层必须过滤**（`.replace(/^\[Mock\]\s*/, '')`）。任何 `{{ item.title }}` / `{{ user.name }}` 上屏前都要去前缀，否则像 KnowledgeCard 标题那样把 `[Mock]` 漏给用户。
- 大改派 agent 要「小而聚焦」：整页大任务易 socket 断线，拆成单组件 / 单 prototype 的小任务更稳（已验证）。
